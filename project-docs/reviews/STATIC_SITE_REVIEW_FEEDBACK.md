## それぞれの説明

### 1. お知らせの中のメモ書きを置き換える

制作中に書いたメモが、そのままページの文章として表示されています。

おそらく分かっている思いますが念のために

| ページ | 表示されている文章 |
| --- | --- |
| index / archive | 「タイトルの文字数２０文字台前半にしてもらうのがいい」 |
| index / archive | 「上のやつで25文字程度だからそれくらい上限かなぁ」 |
| index / archive | 「25字以上になったら「…」で省略するようにするか」 |
| archive | 「1ページに10件載せてそれ以降は」「ページネーション入れる（いつものヤツ）」「月別フィルター か カテゴリフィルター を入れたい」 |
| single | 「＜ここに本文が入る＞」「メイン幅 1100px（or 1150px）／ギャップ 100px（or 50px）／サイドバー幅 400px／の予定」「○○担当です！」 |

お知らせの中身は「本物っぽい文章」にしておくと、見た人がイメージしやすくなります。

- 「6月の営業日についてのお知らせ」
- 「夏まつりを開催しました」
- 「送迎車を1台増やしました」

WordPressにすると、お知らせは**記事（投稿）として管理画面から入力する**ようになります。
つまり、この文章はテーマ（デザイン）側には残りません。
ただし**サンプルとして見せている間はこの文章が全てなので、ここを整えるのが一番効きます。**

### 2. メニューの文字色を変える

以下は例なので参考程度にしてください。
実際に試してどのように見えるか確認することをお勧めします。

| 文字色と背景の組み合わせ | 読みやすさ（コントラスト比） | 判定 |
| --- | --- | --- |
| メニューの黄緑 `#93d341` ＋ クリーム `#fff4e6` | **1.66 : 1** | 基準は 4.5:1。かなり下回っています |
| 同じパレットの濃い緑 `#4b6c08` ＋ クリーム | **5.61 : 1** | ◎ 十分読めます |

コントラスト比というのは「文字と背景の明るさの差」の数字で、**4.5:1 以上**あれば多くの人が読めるとされています。
1.66 だと、明るい場所や、目が見えにくい方には、ほとんど読めません。
介護のサイトは**ご高齢の方やそのご家族**が見るので、ここは特に大事なところです。

やることはシンプルで、CSS変数を差し替えるだけです。

```css
/* メニューの文字色 */
color: var(--palette-green-04); /* #4b6c08 濃い緑 */
```

**黄緑（#93d341）が悪い色というわけではありません。**
「文字の色」には向いていないだけなので、**線・下線・ホバーしたときの背景・アイコン**など、
読まなくていい飾りの部分に使うと、とても良い差し色になります。

いま実際、メニューの「施設紹介」「ご利用の流れ」だけは濃い緑で表示されています。
並べて見ると、そちらの方が読みやすいのが分かると思います。

### 3. オレンジを「文字の色」に使うのをやめる

同じことが、オレンジでも起きています。

| 場所 | 組み合わせ | 読みやすさ | 判定 |
| --- | --- | --- | --- |
| 送信ボタン | 白文字 ＋ オレンジ `#f78407` | **2.54 : 1** | ✕ |
| フッターのリンク | オレンジ `#f78407` ＋ 薄緑 `#dcf6d2` | **2.20 : 1** | ✕ |
| プライバシーポリシーのリンク | オレンジ `#f78407` ＋ `#fff4ee` | **2.35 : 1** | ✕ |
| 「お問い合わせフォーム」ボタン | `#333` 文字 ＋ 薄オレンジ `#ffcb8f` | **8.54 : 1** | ◎ とても良い |

一番押してほしい「送信」ボタンが、一番読みにくくなってしまっています。

でも、最後の行を見てください。**`#333` の文字＋薄いオレンジの背景は 8.54:1 で、とても優秀です。**
つまり**色えらび自体は良くて、「どの色を文字に使うか」が決まっていないだけ**なんです。

そこで、色の役割をこう決めてしまうのがおすすめです。

| 役割 | 使う色 |
| --- | --- |
| ページの背景 | `#fff` / `#fff4e6` |
| カードやボックスの背景 | `#dcf6d2` / `#fff4ee` |
| 本文の文字 | `#333` |
| 見出し・メニュー・リンクの文字 | `#4b6c08`（濃い緑） |
| ボタンの背景（ふつう） | `#ffcb8f` ＋ 文字は `#333` |
| ボタンの背景（一番押してほしいもの） | `#f78407` ＋ 文字は `#333`。白文字にしたいなら、オレンジをもっと濃く（`#c25e00` くらい）する |
| 線・ホバー・アイコン | `#93d341`（黄緑） |

**「オレンジは背景の色。文字にはしない」**——これ1つ覚えておくだけで、サイト全体が一気に読みやすくなります。

いま緑が4種類・オレンジが6種類で合計10色あります。
少し多いので、上の表のように「役割ごとに1色」と決めると、まとまりが出ます。

### 4. 写真の上の白い文字を、画像の下に出す

トップページ「サービスの概要」の「デイサービス」「訪問介護」「居宅介護支援」の文字です。
明るい写真の上に白い文字をのせているので、ほとんど読めない状態になっています。

**影はちゃんと付けてくれているんです。** 今こうなっています。

css

```css
color: #fff;
font-size: 32px;
font-weight: 500;
text-shadow: 0 2px 10px rgba(0, 0, 0, 0.58);
letter-spacing: 8.96px;
```

それでも読めないのには、理由が3つあります。

- **背景が白い壁の写真**なので、白い文字 vs ほぼ白。影で埋められる差ではありません
- **ぼかし10px・濃さ0.58** は「ふわっとした光」で、文字の輪郭を作るタイプの影ではありません
- **字間が8.96px（0.28em）開いている**ので、1文字あたりの影がさらに薄まっています

`font-weight: 500` も、32pxで写真の上にのせるには少し細めです。

#### おすすめは「画像の上に文字を置かない」

いくつかやり方はありますが、**このサイトでは、見出しを画像の下に出すのが一番いい**と思います。

html

```html
<figure class="service-card">
  <img src="./images/service_01.jpg" alt="デイサービスで体操をする利用者">
  <h3 class="service-card__title">デイサービス</h3>
  <p>
    日中の時間を安全に過ごし、体操や活動を通して生活リズムを整えます。<br>
    送迎・食事・入浴（任意）にも対応いたします。
  </p>
</figure>
```

写真は明るいまま見せて、文字は濃い色（`#4b6c08` か `#333`）でしっかり読ませる。
すぐ下に説明文があるので、見出しもそこに置いた方が、情報のまとまりとしても自然です。

#### なぜ「フィルターをかける」より、こちらをすすめるのか

理由は2つあります。

**1つめは、このあとWordPressにするからです。**

フィルターの濃さで解決すると、「写真の明るさに合わせてフィルターを調整する」という前提ができてしまいます。
でも本番では、施設の方が管理画面から写真を差し替えます。
次に入る写真が明るいか暗いかは、作った側にはもう分かりません。
**運用が始まってから、施設の方の手元で読めなくなる**——これは避けたいところです。

**2つめは、この写真の主役が「笑顔」だからです。**

文字が読める濃さにするには、`rgba(0, 0, 0, 0.45)` くらいのフィルターが必要になります。
そうすると、利用者さんの笑顔がそのぶん暗くなります。
介護のサイトで一番伝えたいのは、まさにその表情のはずです。
**文字を読ませるために、一番の売りを暗くしてしまう**のはもったいないです。

#### どうしても画像の上に置きたいときは

全面にフィルターをかけるより、**文字の後ろにだけ帯を敷く**方が向いています。
写真の明るさを保ったまま、文字も読めます。

css

```css
.service-card__title {
  background: rgba(255, 255, 255, 0.85);
  color: var(--palette-green-04); /* #4b6c08 */
  padding: 8px 24px;
  letter-spacing: 0.1em; /* 8.96px → 3.2px くらいに詰める */
}
```

#### あわせて直したいこと

この「デイサービス」、いま `<figcaption>` になっています。

見た目は見出しなのですが、HTMLとしては見出しとして扱われません。
そのため、読み上げソフトの「見出しだけを拾って移動する」操作で飛ばされてしまいますし、
検索エンジンからも見出しとして読まれません。

画像の下に出すタイミングで、**`<h3>` に変えておく**と一石二鳥です。

### 5. 画像を軽くする

いま、トップページを開くのに **3.4MB** かかっています。目標は **1MB以下**です。

| ファイル | 今の重さ | 気づいたこと |
| --- | --- | --- |
| service_01.jpg | 1,129KB | 1920×1280 のまま置いています |
| MainVisual_pc.png | 647KB | **写真なのにPNGで書き出しています** |
| Button001〜005.png | 各63〜77KB | 300×200のPNG。まとめて軽くできます |
| service_02.jpg | 149KB | 640×427 を 1369×274 で表示 → **引き伸ばされてぼやけています** |

ポイントを3つだけ。

- **写真はJPEGかWebPで書き出す。** PNGは「イラスト・ロゴ・透明が必要なもの」用です。写真をPNGにすると、同じ見た目でも3〜5倍重くなります。
- **表示する大きさより大きく書き出さない。** 横1200pxで表示するなら、書き出しは横2400pxまで。
- **表示する大きさより小さい画像を引き伸ばさない。** service_02.jpg がこれに当たります。ぼやけて見えるのはこのためです。

いまは `width` / `height` 属性と `loading="lazy"` も付いていないので、
読み込み中に画面がガタッと動いたり、下の方の画像まで最初に全部読み込んでしまっています。

**WordPressにすると、この2つは自動でやってくれます。**
メディアライブラリに入れた画像は自動で複数サイズが作られ、`width` / `height` と `loading="lazy"` も自動で付きます。
ただし**元の画像が重いままだと意味がない**ので、**アップロードする前に軽くしておく**のが大事です。
（`functions.php` で `add_image_size()` を使うと、必要なサイズを自分で追加できます）

表示の速さは、見ている人が「この会社は大丈夫そう」と感じるかどうかに直結します。
制作物のサンプルなら、なおさら効いてくるところです。

### 6. 「ご利用の流れ」を画像からHTMLに作り直す

これは少し大きな話ですが、**一番学びが大きいところ**なので書きます。

`about_us.html` の「ご利用開始までの流れ」、01〜08 のカードが**すべてSVG画像**になっています
（flow11-pc.svg 〜 flow18-pc.svg）。デザインツールで作ったものを、そのまま貼っている状態です。

見た目はきれいなのですが、画像だとこうなります。

- 文字を選択できない・ページ内検索で見つからない
- 読み上げソフトが本文を読めない（`alt` の見出しだけ読まれます）
- スマホで幅に合わせて縮むので、文字も一緒に小さくなる
- 文言を1文字直すのに、デザインツールに戻って書き出し直しになる
- 検索エンジンから見ると、そこに文章が無いのと同じ

そして **WordPressにすると、ここが一番困ります。**
施設の方が管理画面から「流れ」の文言を直したくても、画像なので直せません。
毎回、制作した人に連絡して画像を作り直してもらうことになります。

HTMLで組み直すと、こう変わります。

- ACF（Advanced Custom Fields）やブロックエディタで、**施設の方が自分で文言を編集できる**
- ステップの追加・削除も管理画面からできる
- 文字が小さくならない・読み上げできる・検索に載る
- 色や余白をCSSで後から調整できる

作り方のイメージです。

```html
<ol class="flow-list">
  <li class="flow-item">
    <span class="flow-item__num">03</span>
    <h3 class="flow-item__title">見学予約</h3>
    <p class="flow-item__text">
      お電話・お問い合わせフォームから承っております。<br>
      パンフレットなどの資料請求・見学のご案内をいたします。
    </p>
    <a href="./contact.html" class="button">お問い合わせフォーム</a>
  </li>
</ol>
```

番号は `<span>`、見出しは `<h3>`、説明は `<p>`。背景の色や角丸はCSSで付けます。
**画像で作れているということは、完成形が頭にある**ということなので、
それをHTMLとCSSに翻訳するだけです。むずかしくありません。

### 7. ボタンの大きさと字の間隔を整える

「03 見学予約」のカードは画像なのに、**「お問い合わせフォーム」ボタンだけHTMLで、画像の上に重ねて置いています。**
実際に測るとこうなっていました。

```
カードの画像   1200 × 214px
ボタン          400 × 100px

カードの上端 → ボタンの上端   100px
ボタンの下端 → カードの下端    14px   ← ここ
ボタンの右端 → カードの右端    72px
```

**上が100pxで下が14px。7倍ちがいます。**
左の文章は画像の中に焼き込まれた余白、ボタンはCSSの座標——別々のルールで置かれているので、
CSSをどれだけ調整しても揃いません。6番でHTMLに作り直すと、この問題は自然に消えます。

ボタン自体についても2つ。

- **400×100px は大きすぎます。** 280×64px くらいが標準的です。今はカードの幅の3分の1、高さの半分近くを占めています。
- **字の間隔が開きすぎです。** `letter-spacing: 9.6px`（0.4em）だと「お 問 い 合 わ せ」がバラバラに見えます。`0.05em` くらいまで詰めると、ぐっと締まります。

同じことが「送　　信」「見 学 予 約・ご 相 談 は」でも起きています。
**日本語は字間を空けすぎると、単語のかたまりが見えなくなって読みにくくなります。**

あと、ボタンの角丸が6pxなのに対してカードの角丸はもっと大きいので、
**角丸の数値も2〜3種類に決めて使い回す**と統一感が出ます（例：小さい要素8px、カード16px）。

### 8. 余白を「外は詰めて、中は開ける」に直す

今のサイトは、**逆になっています。**

- セクションとセクションの間 → 画面1つ分近く空いている（トップページの全長は11,000px）
- カードの中 → ボタンの下が14pxしかない

これを逆にすると、ぐっと読みやすくなります。

- セクションの間隔は今の**半分**くらいに
- カードの中の余白は**上下左右そろえて32〜40px**くらいに

余白は「多ければ上品」ではなく、**「関係のあるものは近く、関係のないものは遠く」**が基本です。
見出しとその説明文は近づける、次のセクションとは離す、という考え方です。

あわせて気づいたところ。

- カードの背景に**斜めの格子模様**が入っていますが、文字の後ろにあると少し読みにくくなります。文字の背後は無地にして、模様を使うならセクション全体の背景に薄く敷くと上品にまとまります。
- トップの「選ばれる理由」の 01/02/03 の位置が、01は右上・02は見出しの左に密着・03は右上とバラバラです。どれか1つに統一しましょう。
- スマホでカードが5枚（奇数）の2列になっていて、最後の1枚が取り残されています。並びを見直すか、6枚にすると整います。
- 写真が横1600×320（5:1）のような細長い帯に切られていて、人物の顔が切れやすくなっています。**3:1 くらいまで**に留めると安心です。

### 9. meta description・OGP・favicon を入れる

全9ページとも、この3つが入っていません。

- **meta description** … 検索結果に出る説明文。無いと、Googleがページの一部を勝手に抜き出して表示します
- **OGP** … LINEやSNSでURLを送ったときに出る、画像とタイトル。無いと**真っ白なリンク**になります
- **favicon** … タブに出る小さいアイコン

サンプルサイトこそ、URLを送って見てもらう機会が多いので、ここは入れておきたいところです。

**WordPressなら、プラグインで一括管理できます。**`SEO SIMPLE PACK`（日本語で分かりやすい）か `Yoast SEO` を入れると、
description も OGP も、記事ごとに管理画面から設定できるようになります。
faviconは「外観 → カスタマイズ → サイト基本情報 → サイトアイコン」から設定できます。

### 10. ページタイトルの書き方をそろえる

いま、ページごとに書き方がバラバラです。

| ページ | 今のタイトル |
| --- | --- |
| index | ひだまりケア旭川 | 社会福祉法人 ひだまり福祉計画 |
| about_us | 施設紹介 **-** ひだまりケア旭川 | 社会福祉法人 ひだまり福祉計画 |
| price | 料金表 | ひだまり福祉計画（「ひだまりケア旭川」が消えている） |

about_us だけ区切りが `-` になっていて、他のページからは施設名が抜けています。
**`ページ名 | ひだまりケア旭川`** の形に統一しましょう。

もう1つ、**呼び名のゆれ**もあります。

## フォームについて（本番にするときの話）

いまのフォームは仮で置いているものだと思います。実際、中を見るとこうなっていました。

- `action` が指定されていないので、送信先がない
- JavaScriptは `preventDefault()` して `reset()` するだけ（＝入力を消しているだけ）
- 送信しても「ありがとうございました」のようなメッセージが出ない

**サンプルとして見せている間は、これで問題ありません。**
ただ、お客さまが押してしまうと「壊れているのかな」と思われるので、
フォームの近くに一言だけ添えておくと親切です。

```html
<p class="form-note">※こちらはサンプルサイトのため、実際には送信されません。</p>
```

**本番のサイトにするときは、WordPressのフォームプラグインを使います。**
自分でPHPのメール送信を書くと、迷惑メール対策やスパム対策まで自分で面倒を見ることになるので、
実務ではプラグインを使うのが普通です。

| プラグイン | 特徴 |
| --- | --- |
| **Contact Form 7** | 一番使われている。情報が多いので困ったとき調べやすい |
| **Snow Monkey Forms** | 確認画面が標準で付く。日本製で分かりやすい |
| **MW WP Form** | 確認画面・自動返信メールが得意 |

介護施設のフォームなら、**確認画面が付くもの**がおすすめです。
ご高齢の方やご家族が入力するので、「送信前にもう一度確かめられる」だけで安心感がまったく違います。

本番にするとき、あわせてやっておきたいこと。

- **スパム対策**（reCAPTCHA か Akismet）。対策なしだと、迷惑メールが1日何十通も届きます
- **自動返信メール**。送った側に「受け付けました」が届くようにする
- **送信完了メッセージ**。ページ内に出るか、サンクスページに移動するか
- **`<label>` と入力欄を紐づける**（今は `for` と `id` が付いていません）
こうすると、ラベルをタップしただけで入力欄が選ばれます。読み上げソフトにも正しく伝わります。

    ```html
    <label for="name">お名前</label><input type="text" id="name" name="name" required>
    ```

- **`autocomplete` を付ける**（`autocomplete="name"` `autocomplete="email"`）。スマホで入力が一気に楽になります
- **電話番号をリンクにする**。`<a href="tel:0166xxxxxx">0166-xx-xxxx</a>` にすると、スマホでタップして発信できます。介護のサイトでは**フォームより電話の方がよく使われる**ので、ここは効果が大きいです

## WordPressで組むときのメモ

今の静的サイトを、どうWordPressに移すかの見取り図です。

| 今のファイル | WordPressでの担当 |
| --- | --- |
| index.html | `front-page.php`（トップ固定ページ） |
| about_us / price / facilities / faq / contact / privacy | 固定ページ ＋ `page-xxx.php` |
| archive.html | `archive.php`（お知らせ一覧） |
| single.html | `single.php`（お知らせ詳細） |
| css/style.css | テーマの `style.css`（CSS変数はそのまま使えます） |
| js/main.js | `functions.php` から `wp_enqueue_script()` で読み込む |

考えておくとよいこと。

- **お知らせは「投稿」で作る。** 今の「ニュース／ブログ」のラベルは、**カテゴリー**で作ると管理画面から増やせます。カラーバッジもカテゴリーのスラッグでCSSを出し分けられます
- **メニューはWordPressのメニュー機能に。** 「外観 → メニュー」で施設の方が並び替えられるようになります。今いるページを強調する処理も、`current-menu-item` クラスが自動で付くのでCSSだけで済みます
- **更新される文章はACFかブロックエディタで編集できるように。** 特に「ご利用の流れ」「料金」「よくあるご質問」は、施設の方が自分で直したいはずの場所です。ここが画像やハードコードだと、毎回連絡が来てしまいます
- **画像はメディアライブラリ経由に。** `width` / `height` と `loading="lazy"` が自動で付きます
- **パンくずはプラグインか自作の関数で。** 今は手書きなので、ページを足すたびに手作業になります
- **CSSは分割を検討。** 今 `style.css` が3,952行（90KB）あります。共通・パーツ・ページごと、くらいに分けると探しやすくなります。分けない場合も、目次コメントを先頭に置くと後で助かります
