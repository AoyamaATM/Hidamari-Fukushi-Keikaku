## 作成時のスクリーンショット記録

- 基本幅：1920px、1600px、1024px、768px、430px
- ブレークポイント直後：1599px、1023px、767px、429px
- PC版全体画像：1600px
- 作成時は全9ページの確認画像を `visual-check/` に生成した。これらはローカル確認用の生成物でGit管理対象外のため、現在のリポジトリから参照できないリンクは整理時に削除した。
- 現在の確認画像は、リポジトリルートで `pnpm run check:visual:pc` または `pnpm run check:visual:sp` を実行して再生成できる。

## ブレークポイントごとの変更概要

- 1920px：既存PC版の横並びナビゲーション、複数列、文字サイズを維持。
- 1600px以下：共通コンテナと左右余白を段階的に調整し、PCレイアウトを保ったまま画面内へ収める。
- 1024px以下：ヘッダーをメニューボタンへ切り替え、固定幅や複数列を縮小・再配置する。
- 768px以下：ページ固有の2列・複数列を原則1列へ変更し、見出し、余白、ボタンをタブレット縦向けに調整する。
- 430px以下：スマートフォン用ヒーロー、16px基準の左右余白、最大386pxの主要コンテンツ幅を使用し、文字と操作領域を調整する。
- 1599px、1023px、767px、429px：各境界を1px下回った状態で、急な崩れや横はみ出しがないことを比較するための確認幅。

## 作成時の確認観点

1. 1024pxでPCナビゲーションからメニューボタンへ切り替えるタイミングが自然か。
2. 768px以下で複数列を1列化した際の情報量と縦方向の長さが適切か。
3. 430pxでのロゴ、メニューボタン、主要見出し、CTAの大きさと余白が適切か。
4. Aboutのスマートフォン用「ご利用の流れ」画像と、Facilitiesの施設情報の並び順が読みやすいか。
5. Priceの768px以下で、料金表だけを横スクロールさせる仕様が分かりやすいか。
6. FAQの長い質問、Contactフォーム、Privacyの長文が430pxで読みやすいか。
7. Archiveの絞り込み・一覧と、Singleで記事の後に移動するサイドバーの順序が自然か。
8. 768px・430pxで縦並びになるフッターの情報順と間隔が適切か。

## 保留事項・注意点

- 現時点で、表示を妨げる保留事項はありません。
- Priceの768px以下では、料金表内だけに横スクロールを残しています。ページ全体の横スクロールではなく、内容を省略しないための意図した仕様です。
- 数値付き画像は初期表示の比較用です。ページ下部の詳細は各HTMLを開いて確認し、PC版との全体比較には1600px全体画像を使用してください。
- このステップではレビュー資料とスクリーンショットだけを追加し、HTML、SCSS、CSS、JavaScriptは変更していません。
