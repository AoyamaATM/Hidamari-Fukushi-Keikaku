# Forminator仕様・運用マニュアル

## この文書について

この文書は、Forminatorの一般的な考え方と、ひだまりケア旭川サイトで実際に採用している設定をまとめたものです。

- 一般仕様: Forminatorで何を設定できるか
- 現行設定: このサイトのフォームがどう動くか
- 運用手順: 安全な変更、確認、障害切り分け

2026-08-18時点のLocal検証環境はForminator 1.57.0です。プラグイン更新後は画面名や設定位置が変わる場合があるため、更新前にステージングで再確認してください。

## Forminatorとは

Forminatorは、WordPress管理画面のビジュアルビルダーでフォームを作り、ショートコードでページへ埋め込むフォームプラグインです。通常の問い合わせフォームに加えて、アンケート、クイズ、計算、決済連携なども扱えます。

問い合わせフォームでは、主に次の設定を1つの編集画面で管理します。

| 設定領域 | 主な役割 |
|---|---|
| Fields | 入力欄、ラベル、必須、入力チェック、複数ページ |
| Appearance | 色、余白、入力欄などの外観 |
| Behavior | 送信方法、入力チェック、送信後の表示、honeypot、保存方針 |
| Email Notifications | 管理者通知、自動返信、件名、本文、宛先、Reply-To |
| Integrations | 外部サービスとの連携 |
| Forminator Settings | CAPTCHA、保存、プライバシーなどのプラグイン共通設定 |

このサイトでは、確認画面、管理者通知、自動返信、完了表示、スパム対策、送信データの保存方針をまとめて扱いやすいことからForminatorを採用しています。Contact Form 7では実現できないという意味ではなく、この案件の要件との相性で選定しています。

## フォームが動く仕組み

大まかな流れは次の通りです。

1. Forminatorで入力欄、確認画面、通知、完了表示を設定する。
2. Forminatorがフォームごとの数値IDを発行する。
3. テーマがそのIDを使い、`[forminator_form id="..."]` ショートコードを実行する。
4. 利用者が入力し、Forminatorの入力チェックを通過するとメール通知と完了処理が動く。
5. DB保存を有効にしている場合だけ、管理画面の「Submissions」に送信内容が残る。

重要なのは、**メール送信とDB保存は別の設定**だという点です。DB保存を無効にしても通知メールは送れます。一方、保存しない構成では「Submissions」に履歴が残らないため、メール不達時に管理画面から本文を復元できません。

## このサイトの現行設定

### 基本情報

| 項目 | 現行値 |
|---|---|
| フォーム名 | お問い合わせ |
| 種別 | 通常フォーム |
| 公開状態 | 公開 |
| 画面構成 | 入力、確認の2ページと送信後の完了表示 |
| 入力チェック | 送信時、インライン表示あり |
| 送信方法 | AJAX |
| 送信中表示 | `送信中…` |
| 送信ボタン | `送信` |
| DBへの送信内容保存 | 無効 |
| 有効期限 | なし |
| honeypot | 有効 |
| Akismet連携 | 無効 |
| Turnstile | Localでは未設定。本番用の設定・確認が必要 |

フォームの数値IDは環境や復元方法によって変わる可能性があります。特定の番号を運用資料やテーマへ直書きせず、WordPressオプション `hidamari_forminator_form_id` を参照します。

### 入力項目

| 表示名 | Forminator内のID | 種類 | 必須 | 補足 |
|---|---|---|---|---|
| お名前 | `name-1` | Name | 必須 | ブラウザー自動入力を有効 |
| メールアドレス | `email-1` | Email | 必須 | 形式チェック、ブラウザー自動入力を有効 |
| お問い合わせ内容（件名） | `text-1` | Text | 必須 | 管理者通知の件名にも使用 |
| 本文 | `textarea-1` | Textarea | 必須 | 問い合わせ本文 |
| 個人情報の取り扱い | `consent-1` | Consent | 必須 | プライバシーポリシーへリンク |

必須項目が空の場合は `必須項目です。`、同意がない場合は `プライバシーポリシーへの同意が必要です。`、メール形式が不正な場合は専用エラーを表示します。

### 確認と完了

- 入力ページの次ボタン: `入力内容を確認`
- 確認ページの戻るボタン: `入力画面へ戻る`
- 確認ページ: お名前、メールアドレス、件名、本文をマージタグで表示
- 送信後: お礼と担当者からの連絡案内、電話番号、受付時間を表示
- 電話番号と受付時間: 「設定 > ひだまり設定」の共通値を、フォーム作成時に完了メッセージへ反映

Forminatorのマージタグは、入力値やサイト情報を通知文・確認表示へ差し込む記号です。たとえば `{email-1}` はメールアドレス欄、`{all_fields}` は全入力欄、`{site_url}` はサイトURLを表します。入力欄を作り直してIDが変わると、確認画面や通知に古いタグが残ることがあるため注意してください。

### メール通知

| 通知 | 宛先 | 件名 | Reply-To | 用途 |
|---|---|---|---|---|
| 管理者通知 | WordPressの管理者メールアドレス | `【お問い合わせ】{text-1}` | `{email-1}` | 担当者が問い合わせを受け取る |
| お問い合わせ自動返信 | `{email-1}` | `お問い合わせを受け付けました｜ひだまりケア旭川` | 未指定 | 利用者へ受付内容を返す |

Local投入スクリプトは、実行時点の「設定 > 一般」の管理者メールアドレスを管理者通知の宛先へコピーします。その後に一般設定だけを変更しても通知先が自動追従するとは限らないため、公開前にForminatorの通知設定を開き、施設側が承認した実際の受信先になっていることを確認してください。

`From`と`Reply-To`は役割が異なります。

- `From`: サイトがメールを送る差出人。公開ドメインやSMTPのルールに合うアドレスを使う。
- `Reply-To`: 受信者が返信ボタンを押したときの宛先。このサイトでは利用者が入力した `{email-1}` を使う。

ホスティングやSMTPプラグインの設定が、Forminator側のFrom名・Fromアドレスを上書きする場合があります。メールが届かない場合はForminatorだけでなく、WordPressのメール送信、SMTP、DNSのSPF・DKIM・DMARC、迷惑メール判定も確認します。

## テーマとの接続

Local投入スクリプト [`tools/local-contact-fixtures.php`](../../tools/local-contact-fixtures.php) がForminatorのフォームを作成または更新し、現在のフォームIDを `hidamari_forminator_form_id` へ保存します。

テーマは次の共通部品でそのIDを取得し、Forminatorのショートコードを実行します。

- [`template-parts/common/contact.php`](../../wordpress/themes/hidamari-care-asahikawa/template-parts/common/contact.php): お問い合わせページ側
- [`template-parts/common/contact-form.php`](../../wordpress/themes/hidamari-care-asahikawa/template-parts/common/contact-form.php): 共通フォームパネル

Forminatorが無効、ショートコードが未登録、またはフォームIDが未設定の場合は、壊れたフォームの代わりに「準備中」と電話案内を表示します。

## 管理画面で確認・変更する場所

1. WordPressへ管理者でログインする。
2. 「Forminator > Forms」を開く。
3. 「お問い合わせ」の「Edit」を開く。
4. Fields、Behavior、Email Notificationsを必要な範囲だけ変更する。
5. 「Update」で保存する。
6. お問い合わせページをシークレットウィンドウで開き、入力から完了まで確認する。

プラグイン更新によりメニューの日本語表記や位置が変わることがあります。判断に迷う場合は、Forminator公式マニュアルの該当バージョンを優先してください。

## 安全な変更手順

1. 変更前にWPvividでDBとファイルを含むバックアップを取得する。
2. 変更目的、現行値、変更後の期待値を記録する。
3. Fields、Behavior、Email Notificationsなど、1区分ずつ変更する。
4. 保存後、入力、必須エラー、確認、戻る、入力保持を確認する。
5. ステージングで最終送信し、管理者通知、自動返信、Reply-To、完了表示を確認する。
6. メールヘッダー、迷惑メール判定、SPF・DKIM・DMARC、SMTPログも確認する。
7. 問題がなければ同じ変更を本番へ反映し、もう一度送受信を確認する。

Localではサンプルサイトの注意書きがあるため、実在する個人情報を入力しないでください。管理者アドレス、SMTP認証情報、Turnstileの秘密鍵などもGitへ保存しません。

### 投入スクリプトの注意

`tools/local-contact-fixtures.php` は再実行時に同じフォームを見つけて、コードに記載されたFields、Behavior、Email Notificationsで更新します。重複は作りませんが、**管理画面だけで変更した設定はスクリプト再実行により上書きされる可能性があります**。

- Localを再構築するとき: スクリプトを基準にする。
- 管理画面で恒久変更したいとき: 先にスクリプト側へ同じ変更を反映する。
- 本番固有の宛先、SMTP、Turnstileキー: Gitへ書かず、環境側で設定する。
- 手動変更後: 理由と設定値を運用記録へ残し、スクリプトを不用意に再実行しない。

## 確認チェックリスト

### 画面と入力

- [ ] お問い合わせページにフォームが表示される
- [ ] お名前、メール、件名、本文、同意がすべて必須になる
- [ ] 不正なメール形式でエラーになる
- [ ] 「入力内容を確認」で確認ページへ進む
- [ ] 確認ページに入力値が正しく表示される
- [ ] 「入力画面へ戻る」で値を保持して戻る
- [ ] PCとスマートフォンで横はみ出しや操作不能がない

### 最終送信

- [ ] 二重送信されず、送信中表示から完了表示へ変わる
- [ ] 管理者通知が承認済みの宛先へ届く
- [ ] 自動返信が利用者へ届く
- [ ] 管理者通知から返信すると利用者のアドレスが宛先になる
- [ ] 件名、本文、日本語、改行が崩れない
- [ ] 迷惑メール扱いにならない
- [ ] DB保存を無効にしたままなら「Submissions」に本文が残らない

### スパムと障害時

- [ ] honeypotが有効
- [ ] 公開環境でTurnstileを設定し、PC・スマートフォンで通過できる
- [ ] CAPTCHAエラー時の案内が分かる
- [ ] SMTPまたはホスティングのメールログを確認できる
- [ ] フォーム停止時の電話窓口と復旧担当が決まっている

Localの総合確認では、必須エラー、確認、戻る、入力保持まで確認済みです。最終送信、実メール到達、SMTP、Turnstileは本番相当環境での未完了事項です。

## よくある問題

### フォームが表示されない

1. Forminatorがインストール済み・有効か確認する。
2. 「Forminator > Forms」に「お問い合わせ」があり、公開状態か確認する。
3. `hidamari_forminator_form_id` が現在のフォームIDを指しているか確認する。
4. キャッシュを削除し、テーマの準備中表示になっていないか確認する。

### 確認ページへ進めない

1. 画面内の入力エラーと同意欄を確認する。
2. ブラウザーコンソールにJavaScriptエラーがないか確認する。
3. 最適化・キャッシュプラグインを一時的に切り分ける。
4. Page Break、確認用HTML、マージタグのIDを確認する。

### 管理者通知または自動返信が届かない

1. 通知が有効で、宛先のマージタグに誤りがないか確認する。
2. 「設定 > 一般」の管理者メールアドレスを確認する。
3. 迷惑メールフォルダーを確認する。
4. SMTP・ホスティングの送信ログとWordPressのエラーログを確認する。
5. Fromドメイン、SPF、DKIM、DMARCを確認する。
6. 管理者通知だけ、自動返信だけ、両方とも不達かを分けて調べる。

### Submissionsが空

現行設定では送信内容のDB保存を無効にしているため、正常な仕様です。業務上保存が必要になった場合は、保存期間、閲覧権限、削除方法、プライバシーポリシーを先に決めてから有効にします。

### 見た目を変更したい

フォーム構造やラベルはForminatorで、サイト固有のレイアウトと装飾はWordPressテーマで管理します。CSSを変更する場合は、テーマの `assets/scss/style.scss` を編集し、`pnpm run build:css:wordpress` で生成CSSを同期します。Forminatorが生成するクラス名はプラグイン更新で変わる可能性があるため、更新後に表示を再確認します。

## 公開前に決めること

- 管理者通知の正式な受信先と複数担当者への共有方法
- 公開ドメインに合うFromアドレス
- ホスティング標準メールを使うか、SMTPサービスを使うか
- Cloudflare Turnstileのサイトキーと秘密鍵
- 送信内容をDB保存しない方針でよいか
- 問い合わせメールの保管期間とアクセス権
- 障害時の電話案内、ログ確認、復旧担当
- Forminator、WordPress、PHPを更新する手順とステージング確認

## 用語

| 用語 | 意味 |
|---|---|
| ショートコード | WordPress本文やテーマからプラグインの表示を呼び出す記法 |
| マージタグ | 入力値やサイト情報を通知文などへ差し込む記号 |
| honeypot | 人には見えない入力欄などで単純な自動投稿を検知する対策 |
| CAPTCHA / Turnstile | 利用者の操作を確認し、自動投稿を抑える仕組み |
| SMTP | メールを送信サーバーへ渡すための仕組み |
| Reply-To | 受信メールへ返信したときの宛先 |
| Submission | フォームから送信された1件分のデータ |
